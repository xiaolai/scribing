The three that matter

1  Remove semantic-release and codecov, then upgrade the toolchainCritical
package.json

Both are declared, invoked by nothing, and between them account for four critical and twenty-six high advisories. semantic-release exists to publish automatically, which the CI configuration explicitly forbids: “CI must never publish automatically from master.”

Effort ~15 agent-minutes to remove. 2–4 agent-hours plus one CI cycle for the jest, eslint and TypeScript upgrade that follows.

2  Declare jsdom and jest-environment-jsdomHigh
scripts/check-demo.cjs:4  ·  jest-jsdom-env.js:6

Both are imported directly by first-party code and appear in no dependency list. They resolve today only because jest 26 hoists them. jest 28 unbundled the jsdom environment, so the upgrade above breaks both yarn test and yarn check-demo the moment it lands, with an error that reads as unrelated.

Effort ~10 agent-minutes. Must land before any jest change.

3  Reconcile the coverage gate with realityHigh
.codecov.yml  ·  src/fonts/animationMask.ts

.codecov.yml demands 96% project coverage. Measured coverage is 72.94%, nothing uploads to Codecov, and animationMask.ts — 358 lines of mask geometry — sits at 0.71%. Anyone reading the repository concludes coverage is enforced at 96%. It is enforced at zero.

Effort ~30 agent-minutes to reconcile the config. 3–5 agent-hours to build a fast regression net for the geometry.

One decision cannot be deferred. 194.3 MB of untracked font and motor assets are required by five CI steps and by prepublishOnly. No single file breaches GitHub's 100 MB hard limit, so committing them will succeed — and the cost will only become visible later, in every clone, permanently. The current git pack is 56.0 MiB. Decide on Git LFS, a verified download step, or a separate assets repository before the commit, not after.

03Correctness & reliability Medium

SVG pointer coordinates silently unconverted when the transform matrix is unavailableHigh
src/renderers/svg/RenderTarget.ts:64, :74

getScreenCTM() returns null for an element that is not rendered. The optional chain then yields undefined, and the DOM Geometry spec defines matrixTransform(optional DOMMatrixInit matrix = {}) — so undefined becomes an identity matrix and the method returns raw client coordinates.

Failure scenario A writer mounted inside a container that is display:none at first input, or inside a subtree a framework attaches after mount. Every stroke maps to viewport space instead of SVG user space, every match fails, and nothing is logged.

Note The newer FontWriter.point() already guards this exact case by checking the determinant. The older path does not. 

// current
const localPt = this._pt.matrixTransform(this.node.getScreenCTM()?.inverse());
return { x: localPt.x, y: localPt.y };

// suggested — mirrors the FontWriter guard
const matrix = this.node.getScreenCTM();
if (matrix && matrix.a * matrix.d - matrix.b * matrix.c !== 0) {
  const localPt = this._pt.matrixTransform(matrix.inverse());
  return { x: localPt.x, y: localPt.y };
}
return super._getMousePoint.call(this, evt);

06Performance & efficiency Medium

Full SVG teardown and rebuild on every pointermove — including moves that add no pointHigh
src/fonts/FontWriter.ts:649 (handler) · :518 (render)
const last = this.gesture[this.gesture.length - 1];
if (Math.hypot(last.x - point.x, last.y - point.y) * this.transform.scale >= 0.5)
  this.gesture.push(point);
this.render();          // ← unconditional

render() then runs while (this.surface.firstChild) this.surface.removeChild(...) and recreates every glyph path, every committed polyline and the in-progress gesture.

Impact Cost per pointer event is O(glyphs + total committed points). The documented ceiling is 1,024 gestures and 65,536 points on a 32-glyph run, so a long session rebuilds tens of thousands of nodes per event, on the input path, at sampling rates reaching 120 Hz. The distance threshold that was written to limit work does not limit the work that dominates.

Animation frames recompute the full mask, and the cache cannot hit during playbackMedium
src/fonts/animationMask.ts:292 · driven from FontWriter.ts:440, :472

The memo key is `${stroke}:${threshold}` where threshold = fraction * 65535. fraction advances every frame, so the key changes every frame and the cache never hits. Each miss scans all width × height cells, emits clipped triangles at the front, and runs outline(), which builds two Maps over every edge and walks the resulting graph. The SVG path additionally creates a fresh <mask> and a fresh <path> per glyph, per tile, per frame.

Fix Quantise the threshold to the number of distinct visual steps a tile can show, so consecutive frames hit. Reuse the mask elements and update only the d attribute. Attach time is documented at about 1.2 s for 1.87M cells; per-frame playback cost is documented nowhere.

1 MB of scratch allocated per tile for at most 8,193 reachable slotsMedium
src/fonts/animationMask.ts:101

Two Float64Array(65536) indexed by owners[i]. owners is a Uint16Array, but validateAnimation caps strokes at 8,192 and rejects any larger owner, so indices above 8,192 are unreachable. Not a correctness problem — 8× the necessary memory traffic during the most allocation-sensitive phase.

What this codebase does well

Structural validation is genuinely hardened, not decorative

Every validator inspects own property descriptors, rejects non-Object.prototype and non-Array.prototype prototypes, rejects symbol keys, rejects accessor properties, checks that the own-property count matches the array length, and rejects a toJSON hook by name. src/units/provider.ts:60 validates before serialising, specifically so a hidden hook cannot substitute unvalidated data after the check. That ordering is deliberate and correct, and it is the kind of detail most reviews never reach.

Cancellation and lifecycle correctness is systematic

Generation counters, abort controllers and serial numbers guard setCharacter, _setUnit, Quiz, UnitQuiz, FontWriter.setAnimation and both demo scripts. Superseded loads settle rather than hanging. Reentrant callbacks that destroy or restart a writer cannot schedule work on the replacement. This is the failure class that breaks most interactive libraries, and it has clearly been attacked on purpose.

The one deliberate duplication has an automated drift gate

extras/fonts/path-geometry.mjs is generated from its TypeScript source by build-geometry.cjs, and check-assets.mjs regenerates it and asserts byte equality with a message naming the command to run. That is the right way to keep a derived copy honest — and the pattern to reuse for any future derived artefact.

The package check verifies the real tarball, not an approximation

scripts/check-package.cjs runs npm pack, extracts it, asserts no src/, packs/, scripts/ or font binaries leaked in, asserts the bundles retain the upstream copyright and permission notice, asserts HarfBuzz did not leak into the core bundle, loads CJS and ESM entry points, evaluates both browser bundles in a fresh VM context, exercises the optional provider through a mocked fetch, and compiles a strict external TypeScript consumer. Very few libraries verify their published artefact this thoroughly.

Conclusion

Scribing's first-party code is stronger than its surroundings. The validation layer, the cancellation discipline, the packaging verification and the licensing documentation all sit above the standard this kind of library usually meets, and every gate in the repository passes today. There is no critical defect in code that anyone wrote here.

The risk sits in the perimeter. The dependency tree carries fifty-one critical advisories, and the two packages contributing most of them are declared but never invoked — one of them, semantic-release, existing to do precisely what the CI configuration says must never happen. Two dependencies that first-party code imports directly are not declared at all, and they will break the test suite the moment the overdue jest upgrade lands. A coverage gate demands 96% while measuring nothing, over a module sitting at 0.71%. And roughly 1,500 lines of the font runtime, shipped as npm source, are compressed to a density at which review is not possible.

None of these is difficult. The dependency cleanup and the two missing declarations are under half an agent-hour combined. The formatting pass is one agent-hour and fully mechanical. The substantive work — unit tests for the mask geometry, splitting the three highest-complexity functions, and the pointer-move rendering fix — is perhaps eight to twelve agent-hours of focused effort, with clock-time dominated by six or so sequential CI runs during the toolchain upgrade rather than by the edits themselves.

One decision cannot be deferred and is not the auditor's to make: whether 194 MB of font and motor assets enter git history. Five CI steps and prepublishOnly need them, no single file breaches GitHub's hard limit, so the commit will succeed and the cost will only become visible in every subsequent clone.

Production readiness: the library is ready for the technical-preview status it claims. It is not ready to publish until package.json names its actual maintainer, the unused release tooling is gone, and the asset-hosting decision is made — all three of which block or contaminate the first npm publish.
